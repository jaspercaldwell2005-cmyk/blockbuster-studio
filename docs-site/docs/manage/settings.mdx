Open **Settings** from the sidebar (on a phone, from the tab bar at the bottom). Most changes save when you click out of a field.

## AI provider

Connect an AI in **Settings → AI provider** for script writing, scene breakdown and prompt enhancement. Pick **OpenAI-compatible** for Unsloth, llama.cpp, LM Studio, Ollama, OpenRouter and most other servers, or **Anthropic**.

For an OpenAI-compatible server, fill in:

- **Scheme, host and port** — for example `http`, `127.0.0.1`, `8888`.
- **API path** — usually `/v1`; OpenRouter uses `/api/v1`.
- **Model** — press **Find models** to ask the server for its list, then choose one. You can also type an id by hand (Unsloth ids can contain colons, like `unsloth/Qwen3.8-27B-GGUF:UD-Q4_K_XL`).
- **API key** — most local Unsloth/llama.cpp servers accept any token or none; hosted providers need their real key.

Press **Test connection** to send one small prompt, then **Save AI settings**. Unsloth serves its models through llama.cpp's OpenAI-compatible server, which exposes `/v1/models`, so **Find models** lists them automatically.

:::note[The studio runs in Docker]
Inside the studio container, `127.0.0.1` means the container itself, so the studio translates `127.0.0.1`, `localhost` and `::1` to **`host.docker.internal`** automatically. `make container-dev` and `make container-up` add that hostname. You can also enter `host.docker.internal` yourself. If the server only listens on its own `127.0.0.1`, start it on `0.0.0.0` (for example `llama-server --host 0.0.0.0 --port 8888`) so the container can connect. On Windows, if Unsloth runs as a Windows app while Docker runs inside WSL2, use [`make llm-relay`](/manage/run-locally#windows-unsloth-on-windows-docker-inside-wsl2) and port `8889`.
:::

## Download tokens

- **Civitai token**: needed to import some LoRAs from Civitai on the **LoRAs** page, including NSFW ones.
- **Hugging Face token**: raises Hugging Face download limits, and is needed for gated models (ones whose terms you must accept on Hugging Face first), including **LTX-2.5**, the studio's default video engine.

## Models

Shows each group of models your pod downloads and whether it's **Ready**, **Downloading** or **Not enabled**. Features that need a group unlock when it's ready.

If a download is waiting on a gated model, a Hugging Face token field appears right under it. Paste a token there and click **Save**. The download starts within about 15 seconds, with no restart.

Groups that are **Not enabled** were switched off when you deployed. To add one, set its `DOWNLOAD_*_MODELS` variable to `true` with **Edit Pod** in Runpod (see [Choose which models download](#choose-which-models-download)); it downloads on the next start.

LTX-2.5, the default video engine, comes with sound and its own [community license](https://github.com/Lightricks/LTX-2/blob/main/LICENSE-2_x) (free under $10M annual revenue, with a few restrictions — see the license for details). **MiniMax H3** is an alternative you can enable instead; its [community license](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/LICENSE) excludes the US, EU, UK and South Korea unless you get a license from MiniMax.

## Setup and logs

![Setup and logs in Settings](/screenshots/setup-and-logs.png)

Shows how long each step of setup took on this pod — studio ready, video model ready, first video, and so on — timed from when the pod started. Useful for judging how long a fresh pod takes to get going.

**Download logs** saves a file with the studio's logs, model and GPU status, and this setup timeline. It has no passwords, keys or other secrets, so it's safe to attach to a bug report.

## Storage

Shows how much disk the studio's generated files and service logs use.

- **Delete unused output** removes generated images and clips that no project, cast, location or LoRA uses. Favorites and anything still used in a film are kept, so this is the safe way to free space. To delete a specific item instead, open it on the **Create** page and choose **Delete**, or select several items and use **Delete** in the selection bar.
- **Delete logs** clears the server, ComfyUI, voice and model-download logs. Download them first if you're reporting a problem. New logs start from empty.

## Sign out

The **Sign out** button is at the top of the Settings page. Sessions otherwise last 30 days.

## Set keys when you deploy

Set these as environment variables under **Set overrides** on Runpod's deploy page, or later with **Edit Pod**; a pod restart picks up the new value. The Settings page's **AI provider** section is the easier way to connect an AI. `ANTHROPIC_API_KEY` and the `OPENAI_*` variables still work as startup fallbacks for script breakdown and Enhance prompt. `CIVITAI_TOKEN` and `HF_TOKEN` can also be set from **Download tokens** above; if you set one in both places, the Settings page wins. `STUDIO_PASSWORD` works a little differently: when it's set, it replaces the password you created in the studio.

:::warning[Keep secrets out of plain environment variables]
Runpod shows a pod's environment variables in plain text to anyone, and any tool, with access to your Runpod account. Prefer the Settings page for Civitai and Hugging Face tokens. If you do use a variable — for these or for an AI key — create a [Runpod Secret](https://docs.runpod.io/pods/templates/secrets) and set the variable to a reference like `{{ RUNPOD_SECRET_hf_token }}`.
:::

| Variable | What it does |
|---|---|
| `STUDIO_PASSWORD` | Your studio password. Overrides the password you created on first visit. The template's default, `change-me`, counts as not set |
| `ANTHROPIC_API_KEY` | Connects Anthropic for script breakdown and Enhance prompt |
| `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL` | Connects an OpenAI-compatible provider instead |
| `CIVITAI_TOKEN` | Civitai token for LoRA imports |
| `HF_TOKEN` | Hugging Face token |

### Choose which models download

Everything is on by default. To make the install smaller, set a switch to `false` under **Set overrides** before you deploy (or later with **Edit Pod**; a switch turned back on downloads on the next start).

| Variable | Models | About |
|---|---|---|
| `DOWNLOAD_IMAGE_MODELS` | Images (Z-Image Turbo) | 21 GB |
| `DOWNLOAD_EDIT_MODELS` | Edits, camera angles, storyboard frames (Qwen-Image-Edit) | 31 GB |
| `DOWNLOAD_LTX_MODELS` | Video with sound (LTX-2.5) | 40 GB |
| `DOWNLOAD_LTX_IC_MODELS` | Shots that follow a previs (LTX add-on) | 1 GB |
| `DOWNLOAD_LTX_INGREDIENTS_MODELS` | Reference sheets for consistent characters and props (LTX add-on) | 1 GB |
| `DOWNLOAD_VOICE_MODELS` | Character voices (Qwen3-TTS) | 9 GB |
| `DOWNLOAD_PERFORM_MODELS` | Perform (Wan Animate) | 25 GB |
| `DOWNLOAD_MINIMAX_MODELS`, `DOWNLOAD_MINIMAX_REF_MODELS` | MiniMax H3, an optional video engine (off by default; see its license above) | 42 GB each |
| `DOWNLOAD_UPSCALE_MODELS` | 4K export upscale (SeedVR2, off by default) | 9 GB |

## Agent access

An AI agent such as Claude Code can make films in your studio on its own: write the storyboard, render, review each shot and export. It signs in with an **agent token** instead of your password.

The **Agent access** section of Settings has the steps to connect one, including a command you can copy. [Use an AI agent](/guides/agent) walks through it, including the previs skill. **New token** replaces the token, and agents using the old one stop working. If you set the token yourself with the `STUDIO_AGENT_TOKEN` variable, change it in Runpod instead.

:::warning
Anyone with the agent token can use your studio. Keep it as private as your password.
:::
